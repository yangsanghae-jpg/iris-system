# M5 작업 가이드 — 오작업 방지

> **기준일:** 2026-06-10
> **대상:** M5에서 IRIS를 작업하는 모든 세션 (사람·에이전트 공통)
> **상위 사양:** [IRIS V2.5](IRIS_V2.5_계층구조_2026-05-22.md), [V2.5.3.1 M2/M5 동등](IRIS_V2.5.3.1_m2_m5_parity_2026-06-05.md)
> **목적:** M5가 운영 규모 발견을 하는 과정에서 M2와의 분담을 깨거나, 진실원을 잘못 박거나, 사양에 없는 길로 흘러서 오작업하는 패턴을 미리 막는다.

## 0. 한 줄 사상

> **M5는 *운영 규모 발견자*, M2는 *작성·실행자*.**
> 같은 환경 (V2.5.3.1 G1~G5 게이트), 다른 역할.
> M5가 본 것이 코드 결함이라면 보고만 하고 M2가 고친다.

---

## 1. 무게중심 — L4-K 지식센터

- IRIS의 중심은 **L4-K 지식센터 = iris-system**.
- L4-C(iris-gateway, cursor 통합)·코딩 자동화는 *보조 갈래*.
- 사용자가 "지식", "지식센터", "근거 데이터" 말하면 → **L4-K (iris-system)**
- 사용자가 "메모리", "프로필", "writeback", "prefetch" 말하면 → **L3 (iris-memory)** — 다른 컴포넌트
- 둘을 같은 그림에 그릴 때는 항상 별도 박스.

---

## 2. M2 / M5 분담 — 절대 깨지 말 것

| 흐름 | 책임 |
|---|---|
| 사양·코드 작성, commit, push | **M2** |
| git pull, 운영 규모 실행, 발견, 보고 | **M5** |
| 진단, 정정, 새 지시서 | **M2** |
| 재실행, 검증 회신 | **M5** |

**M5에서 절대 하지 말 것:**

- ❌ M5에서 코드 패치를 직접 `git commit/push` (M2 owner)
- ❌ M5의 `_index.db` / FAISS / `eval_runs/` 를 정본으로 push (자기 환경 산출물은 `.nosync/` 또는 `.gitignore`)
- ❌ M5에서 `knowledge/raw/` 직접 추가 (raw 인제스트는 M2 사양 따라 실행)
- ❌ M5에서 새 사양 문서 신설 — 보고서(`M5_*_보고서_*.md`)만 작성

**M5에서 해야 할 것:**

- ✅ 발견한 결함은 *증상 + 재현 데이터 + 환경*만 보고서로 박는다
- ✅ 미커밋 패치(테스트용)는 OK, 단 해당 보고서에 "M2가 commit해야 함" 명시
- ✅ M2 지시서 받으면 `git pull` 후 그대로 재실행, 결과 회신

> **Why (V2.5.1 §11.5, m5_discovery_pattern):** M2 시드 5건에서는 절대 못 잡는 결함을 M5가 reference 630건 환경에서 사전 노출한다 (§17 임베딩 컨텍스트 한계, §18 doc_id 비결정성, §19 FAISS over-fetch 부족). 이 패턴이 깨지면 알다 9089 entity 도달 후 *대규모 회귀*가 터진다.

## 4. iCloud symlink 함정 (2회 발생, 패턴 확인)

**증상:** `0Dev/iris-system`이 dangling symlink → 작업 시작하자마자 깨짐.

**원인:** iCloud는 *경로 자체*를 sync. M5가 `~/iris-system`에 박은 symlink 타겟이 M2에 없는 경로면 양쪽 다 깨진다.

**항구 조치 (M2/M5 동일):**

```
git clone git@github.com:yangsanghae-jpg/iris-system.git ~/iris-system
ln -s ~/iris-system /Users/iris/Documents/0Dev/iris-system
```

**M5 작업 시작 시 첫 점검:**

```
ls -la 0Dev/iris-system
readlink 0Dev/iris-system          # → /Users/iris/iris-system
ls 0Dev/iris-system/apps/          # 비어 있으면 깨진 것
```

`.icloud-backup/`은 LEGACY로 보존 — **새 작업에 쓰지 말 것**.

## 5. iris-hub는 *진도 점검 콘솔* (운영 콘솔 X)

- 시각 레퍼런스: 알다 v0.10.1 (6탭 + 다크 카드) — but **내용은 다름**.
- iris-hub = 시드 5 → 9089 *과정*을 점검. 운영 콘솔 아님.
- :8765 Streamlit 단일유저, 127.0.0.1.
- 별도 repo (`yangsanghae-jpg/iris-hub`).
- v0 = 3탭 (진척/데이터/게이트) active + 3탭 placeholder.

**M5 행동 규약:**

- ✅ Phase 상태는 `python -m scripts.mark_phase {start|done|skip} --version V2.x --phase N`
- ❌ "운영 콘솔"이라고 부르지 말 것 — *진도 점검 콘솔*
- ❌ KPI 차트를 hub에 그리지 말 것 — Grafana iframe (V2.5.1 §11.6)
- ❌ "어디까지 왔지?" 질문에 sqlite 직접 쿼리로 답하지 말고 hub 가리킬 것
- 🔵 `skipped`는 `done`과 동급 (V2.5.3 §3.5 우회 룰)

## 11. M5에서 자주 했던 오작업 (실제 사례)

| 사고 | 패턴 | 정정 |
|---|---|---|
| §17 임베딩 컨텍스트 한계 | M5가 패치 작성 후 직접 commit하려 함 | 미커밋 보고 → M2 commit·push |
| §18 doc_id 비결정성 | 머신별 다른 doc_id를 정본으로 push할 뻔 | content hash 결정성 (M2 설계) |
| §19 FAISS over-fetch 부족 | M5에서 1줄 패치 직접 commit | M5는 결과 보고, M2가 50× over-fetch 박음 |
| iCloud symlink 깨짐 (2회) | M5 절대경로가 M2에 없음 | 양 머신 동일 `~/iris-system` 약속 |

> **공통 원칙:** "M5만의 문제일까?"가 아니라 "코드 결함이고 M5가 발견자". 분담 깨면 알다 9089 규모에서 회귀.
