LLM 调用明细

类型次数说明
主 Agent LLM 调用 100-140 每轮 = 1 次工具调用/响应生成，包含上下文拼接
子 Agent LLM 调用 30-80 6-8 次 spawn，每次 3-10 轮内部 LLM 调用
Skill 调用 1-5 web-access（下载 Logo / 参考官网）、simplify（代码审查）
LLM 调用总计 ~130-220 取决于代码复杂度和 bug 数量

风险与缓解

风险级别缓解措施
Express 5 与 cors 包兼容性 P1 优先测试，必要时换内联 CORS 中间件
TailwindCSS 4 生态不成熟 P1 不依赖第三方 Tailwind 插件，纯用 utility class
SQLite 并发写入 SQLITE_BUSY P1 WAL 模式 + 重试 3 次 + 100ms 间隔
飞书 OAuth 凭证获取困难 P2 降级为"可跳过"，不影响其他步骤
用户本机无 Node.js（双击启动） P2 启动脚本检测并提示下载 Node.js

Agent 架构

参与角色

角色权限何时使用
主 Agent（GLM-5.1） 读写 + 执行 始终在线，做决策、写代码、调工具
Explore 子 Agent 只读 搜索代码/文件，结果汇报给主 Agent
Plan 子 Agent 只读 架构方案分析，建议汇报给主 Agent
general-purpose 子 Agent 读写 独立多步骤任务（如集成测试）

交互模式

主 Agent 每轮 = 拼接上下文（CLAUDE.md + 对话历史 + 工具结果）→ LLM 推理 → 生成回复/调用工具 → 工具本地执行 → 返回结果 → 下一轮。 子 Agent 有独立上下文，完成后返回摘要，自身消亡。对话越长，每轮 token 消耗越多，系统会自动压缩早期对话。
