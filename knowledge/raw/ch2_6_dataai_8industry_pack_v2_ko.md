## 0. Ch2.6 정체성 재정의 (v2)

**Chapter 2 = 선택된 산업·규모·자동화 수준에 따라 필요로 하는 제조 관리 시스템들의 열거**.

**Ch2.6 = 그 중 "데이터의 응용" 영역**. 다음 4 질문에 답한다:

1. **무엇을 (What)** — 어떤 데이터를 관리할 것인가? (사실/시계열/이벤트/마스터·메타/지표/특징·모델)
2. **어디에 (Where/How)** — 어떻게 보관·처리할 것인가? (수집/정제/저장/이력/품질·거버넌스)
3. **어떻게 사용 (Use)** — 어떻게 응용·분석할 것인가? (리포트 → 칸반 → BI/DT → 빅데이터 → AI)
4. **누가 (Who)** — 누가 어떤 도구로 어떤 결정을 하는가? (운영자 → 전문가 → 분석가·데이터엔지니어 → MLOps·도메인 AI)

> Ch2.1~2.5는 **시스템(MES/EAP/QMS 등)** 의 열거, Ch2.6은 그 시스템들이 흘려보내는 **데이터의 응용 스택**.

## 2. 카드별 한국어 데이터팩 (v2)

### 2.6.1 데이터 응용 정체성 (`card6_identity`, 공통)

```text
역할:
  Ch2.1~2.5 의 시스템들이 생성·소비하는 데이터를 통합·정제·분석하여
  운영자·전문가·경영진에게 "결정 가능한 정보" 로 되돌려주는 데이터 응용 계층.

목적:
  - 사실(Transactions/Events) 을 자산화하고
  - 지표(Metrics) 를 표준화하며
  - 분석(BI/예측/시뮬레이션/AI) 으로 운영 폐루프를 좁힌다.

다루는 4 질문:
  1. 무엇을 관리할 것인가  (데이터 자산)
  2. 어디에·어떻게 보관·처리할 것인가  (수집·저장·처리)
  3. 어떻게 응용할 것인가  (리포트·BI·빅데이터·AI)
  4. 누가 무슨 도구로 결정하는가  (성숙도 L1~L4)

다루지 않는 것 (경계):
  - 시스템 자체의 기능은 Ch2.1~2.5 에서 다룬다.
  - 공정 흐름·라우팅·관리점은 Ch1.1 (공정 분석) 에서 다룬다.
  - 경영 분석 결론은 Ch1, ROI 는 Ch6.
```

### 2.6.2 데이터 자산 (`card6_assets`, 산업 × 규모)

> "어떤 데이터를 관리할 것인가" — 산업마다 **데이터 자산의 구성과 가치 가중치** 가 다르다.

**자산 타입 6종 (공통 분류)**

| 코드 | 자산 타입 | 한국어 | 예 |
|------|-----------|--------|----|
| `MD` | 마스터 / 메타 | 마스터·메타 | 제품·BOM·공정·설비·레시피·작업자·KPI 정의 |
| `TX` | 트랜잭션 | 트랜잭션 | 작업지시·이동·생산·검사·출하 |
| `EV` | 이벤트 | 이벤트 | 설비 알람·SECS/GEM·도어·인터록·Excursion |
| `TS` | 시계열 | 시계열 | EAP/Historian 센서·환경·유틸리티 트레이스 |
| `KPI` | 지표 | 지표 | 산업·규모별 매일 보는 운영 KPI |
| `FM` | 특징 / 모델 | 특징·모델 | Feature Store, 학습 데이터셋, 모델 산출물 |

#### 산업별 데이터 자산 매트릭스 (v2 한국어)

각 산업에 대해 6 자산 타입의 **우선순위(P1~P3)**, **대표 객체**, **출처 시스템(Ch2.1~2.5 의 어느 시스템에서 오는가)**, **소비처(누가 보는가)** 를 정의.

##### A. 프로젝트형 제조

- **P1 자산**: 마스터·메타 (MD), 트랜잭션 (TX), 지표 (KPI)
- **P2 자산**: 이벤트 (EV)
- **P3 자산**: 시계열 (TS), 특징·모델 (FM)
- **대표 객체**: 프로젝트·WBS·계약 패키지, 도면 revision, 자재 패키지, 협력사·서류, 진도(시공·시운전 게이트)
- **출처 시스템**: ERP/PPM, 도면 관리, 자재관리, 공정 진도 시스템, 협력사 서류 시스템
- **소비처**: 프로젝트 매니저, 설계·시공·시운전 책임자, 고객 인수 검사
- **핵심 지표(KPI Top 3)**:
  - 게이트 통과율 (FEED·상세설계·기자재·시공·시운전 5 게이트)
  - 장납기 기자재 납기 대비 시공 동기율
  - Punch list severity별 미결 aging

##### B. 반도체 제조

- **P1 자산**: 시계열 (TS), 트랜잭션 (TX), 이벤트 (EV)
- **P2 자산**: 마스터·메타 (MD), 지표 (KPI)
- **P3 자산**: 특징·모델 (FM)
- **대표 객체**: Lot·Wafer·Die genealogy, Recipe·Mask·Reticle, EAP/FDC 트레이스, Defect map, Q-time 큐
- **출처 시스템**: MES, EAP/FDC, RTD/Dispatcher, Recipe Management, 계측·검사 시스템, Historian
- **소비처**: 공정·설비 엔지니어, 수율 분석가, 디스패처 운영, 팹 운영 총괄
- **핵심 지표(KPI Top 3)**:
  - Cycle Time x-factor (계획 대비 비)
  - WIP의 병목 단계 비중 + Q-time 위반율
  - Line Yield / Final Yield 격차

##### C. 전자 조립 제조

- **P1 자산**: 트랜잭션 (TX), 마스터·메타 (MD), 지표 (KPI)
- **P2 자산**: 시계열 (TS), 이벤트 (EV)
- **P3 자산**: 특징·모델 (FM)
- **대표 객체**: WO·BOM revision·ECN cut-in·AVL, Feeder setup·First Article, Serial genealogy, SPI/AOI defect, ICT/FCT 결과
- **출처 시스템**: MES, SMT 라인 SPI/AOI/X-ray, 테스터 (ICT/FCT), Tester program 저장소, AVL/PLM
- **소비처**: 라인 리더, 품질 엔지니어, NPI 매니저, 고객(EMS) 품질
- **핵심 지표(KPI Top 3)**:
  - First Pass Yield (라인·고객·모델별)
  - SPI/AOI false call·miss call 비율
  - 모델 changeover 평균 시간

##### D. 디스플레이·신에너지 제조

### 2.6.3 데이터 수집·저장·처리 (`card6_pipeline`, 규모 S1~S4)

> "어디에·어떻게 흐르고 쌓는가" — **규모**에 따라 파이프라인 토폴로지가 달라진다.

각 단계에 대해 **수집(Ingest) / 저장(Storage) / 처리(Processing) / 거버넌스(Governance)** 4 축 정의.

#### S1 단일 공장 — 일배치 + 사내 RDB

- **수집 (Ingest)**: MES/ERP 트랜잭션 야간 배치, 수기 입력, Excel 업로드
- **저장 (Storage)**: 사내 RDB 한 곳 (운영 DB 직접 조회 또는 야간 dump)
- **처리 (Processing)**: SQL 보고서, 일/주/월 집계
- **거버넌스**: 보고서 양식 표준화 정도. 데이터 품질·이력은 사람 검토
- **데이터 흐름 한 줄**: MES/ERP → 야간 ETL → 사내 RDB → 정형 보고서
- **한계**: 사후 분석 일변도, 라인·공정 단위 모니터링 불가

#### S2 다라인·전문 운영 — 근실시간 + Historian

- **수집 (Ingest)**: MES 실시간 (REST/EDA), Historian 시계열 (1초~1분), SPI/AOI 결과, 칸반 입력
- **저장 (Storage)**: Historian (시계열) + 사내 RDB (트랜잭션) + 라인·공정 마트
- **처리 (Processing)**: 실시간 KPI 계산, 라인·공정 칸반, SPC 차트, 알람 룰
- **거버넌스**: KPI 정의 부분 표준화, 역할별 칸반 권한
- **데이터 흐름 한 줄**: MES + Historian + 라인 검사 → 근실시간 스트림 → 라인/공정 마트 → 전문 보고서·칸반
- **한계**: 다공장 비교 어려움, 예측·시뮬레이션 없음

#### S3 다공장 통합 분석 — Lakehouse + BI + Digital Twin

- **수집 (Ingest)**: 다공장 MES·EAP·Historian·LIMS·EMS 통합, CDC (변경 데이터 캡처), 이벤트 스트림
- **저장 (Storage)**: Data Lakehouse (Bronze/Silver/Gold), 표준 KPI Mart, 메타·MDM 카탈로그
- **처리 (Processing)**: Spark/SQL 배치 + 스트림, BI 셀프 분석, Digital Twin 시뮬레이션, 예측 모델 (1차)
- **거버넌스**: KPI 정의 마스터, 데이터 품질 SLA (완전성·적시성·정확성), Data Catalog, 권한·감사
- **데이터 흐름 한 줄**: 다공장 MES·EAP·Historian → DataPlatform Lakehouse → 표준 KPI Mart → BI / Digital Twin
- **한계**: 모델 운영·재학습이 부분적, 글로벌 KPI 통일 미흡

#### S4 글로벌 통합 운영 — Mesh + MLOps + Feature Store

- **수집 (Ingest)**: 전 팹 데이터 메시 (Data Mesh), 실시간 이벤트 백본 (Kafka·Pub/Sub), Edge → Cloud
- **저장 (Storage)**: 도메인별 데이터 프로덕트, Feature Store (학습/추론 공통), AI Knowledge Warehouse
- **처리 (Processing)**: MLOps (학습·배포·모니터·드리프트·재학습), 글로벌 IMC 통합 모니터링, AI 추론 폐루프
- **거버넌스**: 글로벌 KPI 표준, 모델 라이프사이클·승인, 책임 있는 AI (Bias/Explainability), 규제 대응
- **데이터 흐름 한 줄**: 전 팹 메시 → Global IMC + Feature Store / MLOps → AI 추론·자율 폐루프 → 표준 KPI 거버넌스
- **한계**: 운영 복잡도·조직 변화관리 비용 큼

### 2.6.4 응용 스택 — Report → AI (`card6_applications`, 규모 × 자동화)

> "어떻게 보여주고 분석할 것인가" — 사용자가 보는 **출력의 진화**.

5 단계 응용 레이어:

| 코드 | 응용 형태 | 한국어 | 예 산출물 |
|------|----------|--------|----------|
| `RPT` | 정형 보고서 | 정형 보고서 | 일/주/월 보고서, KPI 출력 |
| `KAN` | 칸반 / 대시보드 | 칸반·대시보드 | 역할별(Q/Eq/Plan) 칸반, 실시간 모니터 |
| `BI`  | BI · 셀프 분석 | BI·셀프 분석 | 드릴다운, what-if, 표준 KPI Mart |
| `BD`  | 빅데이터·시뮬레이션·예측 | 빅데이터·DT·예측 | Digital Twin, 시계열 예측, 시나리오 분석 |
| `AI`  | 산업 AI·자율 폐루프 | 산업 AI·자율 폐루프 | Excursion 자동 분류, 권고 액션, 자율 제어 폐루프 |

#### 규모 × 응용 스택 매트릭스 (한국어, v2)

| 규모 / 응용 | RPT 보고서 | KAN 칸반 | BI 셀프 | BD 예측·DT | AI 자율 |
|-------------|-----------|----------|---------|-----------|---------|
| **S1** | 권장 | 부분 | — | — | — |
| **S2** | 권장 | 권장 | 부분 | — | — |
| **S3** | 권장 | 권장 | 권장 | 부분 | — |
| **S4** | 권장 | 권장 | 권장 | 권장 | 권장 |

각 응용에 대해:

##### RPT 정형 보고서
- **목적**: 사후 결산·실적 보고 (운영 결정에는 한 박자 늦음)
- **사용자**: 경영진·관리자·고객 보고
- **도구**: ERP 보고, Excel, 사내 보고 포털
- **데이터 입력**: 마스터 + 일간 트랜잭션 집계
- **신호**: 표지(헤더)·시계열 차트·표
- **현장 점검 신호**: 보고서 발행 정시성 99% / 양식 표준화율

##### KAN 칸반·대시보드
- **목적**: 근실시간 라인·공정 가시화, 이상 즉시 발견
- **사용자**: 라인 리더·운영자·역할 책임자 (품질·설비·계획)
- **도구**: 라인 모니터, 역할 칸반 (전용 화면), Andon
- **데이터 입력**: 트랜잭션 + Historian 시계열 (1초~1분)
- **신호**: 신호등·게이지·실시간 차트·알람
- **현장 점검 신호**: 알람→조치까지 < 30 분 / 칸반 latency < 1 분

##### BI 셀프 분석
- **목적**: 드릴다운·연관·what-if 로 운영자가 직접 답을 찾음
- **사용자**: 분석가·엔지니어·운영 책임자
- **도구**: BI 도구 (Tableau/Superset/PowerBI 등), 표준 KPI Mart
- **데이터 입력**: 표준 KPI Mart + 차원 (제품·고객·라인·기간)
- **신호**: 인터랙티브 차트·코호트 분석·세그먼트
- **현장 점검 신호**: KPI 정의 마스터 단일화 / 사용자 자가 빌드 비율 ≥ 50%

##### BD 빅데이터·DT·예측
- **목적**: 추세 예측, 시뮬레이션, 다공장 비교, 캐파 평가
- **사용자**: 데이터 분석가·시뮬레이션 팀·R&D
- **도구**: Lakehouse·Spark·Digital Twin·ML 라이브러리
- **데이터 입력**: 시계열 + 이벤트 + 마스터 통합, Feature 1차 생성
- **신호**: 예측 밴드·시나리오 비교·DT 모델
- **현장 점검 신호**: 예측 정확도 (MAPE/RMSE) 모니터 / DT 시나리오 적중률

##### AI 자율 폐루프
- **목적**: Excursion 자동 분류·권고 액션·자율 제어로 폐루프 좁힘
- **사용자**: MLOps·도메인 AI 팀·자동화된 제어 시스템
- **도구**: Feature Store + MLOps + 모델 서빙 + 룰 엔진 + 거버넌스
- **데이터 입력**: Feature Store (학습/추론 공통), 실시간 이벤트 스트림
- **신호**: 모델 추론·신뢰도·드리프트·권고 액션 카드
- **현장 점검 신호**: 모델 드리프트 SLA·재학습 주기 / 권고 채택률·자동화율

### 2.6.5 데이터 성숙도 — L1~L4 (`card6_maturity`, 산업 무관)

기존 V1.52 의 maturity_levels 절을 v2 정체성에 맞춰 evidence 를 보강.

#### L1 보고형 (Reporting)
- **요약**: 정형 보고서로 사후 집계. 단일 공장·일/주/월 단위.
- **신호 (Evidence) — 현장 점검 체크리스트**:
  - 정형 일/주/월 보고서 자동 발행률 ≥ 95%
  - 사후 분석 비중이 90% 이상
  - 이상 발견·대응이 운영자 경험·전화·이메일 중심
  - KPI 정의가 부서별로 상이 (단일 KPI 마스터 없음)
  - 데이터 품질 검토는 사람 손 작업

#### L2 제조 BI (Manufacturing BI)
- **요약**: 셀프 BI·역할 칸반·근실시간 모니터링. 라인·공정 단위 폐루프 시정.
- **신호 (Evidence)**:
  - 역할별 칸반 (Quality·Equipment·Plan) 운영 ≥ 3개
  - 알람→조치 평균 < 30분 (실측)
  - 사용자가 자가 빌드한 BI 보고서 비중 ≥ 50%
  - Historian 1초~1분 트레이스 라인 단위 수집
  - KPI 정의가 라인 단위로는 일치 (공장 간은 일부 격차)

#### L3 데이터 플랫폼 (Data Platform)
- **요약**: Lakehouse 통합·표준 KPI Mart·디지털 트윈. 다공장 비교·예측·시뮬레이션.
- **신호 (Evidence)**:
  - 단일 KPI 마스터로 공장 간 동일 정의 사용
  - 디지털 트윈으로 시나리오 분석을 1회 이상 운영
  - 데이터 품질 SLA 운영 (완전성·적시성·정확성 측정값 공개)
  - Data Catalog 운영 (메타데이터 + 라인age 추적)
  - 1차 예측 모델 (수율·OEE·납기) 운영 중

#### L4 산업 AI·자율 폐루프 (Industrial AI / Autonomous)
- **요약**: Feature Store + MLOps 기반 모델 운영, 글로벌 IMC 표준화, AI 지식 추천과 자율 폐루프.
- **신호 (Evidence)**:
  - 모델 모니터링·드리프트 감지·자동 재학습 운영
  - Excursion 자동 분류 + 권고 액션 제시
  - AI 지식 창고로 사례·룰·모델 자산화
  - 글로벌 KPI 표준화 + 표준 위반 알림 자동화
  - 책임 있는 AI (Bias/Explainability) 정기 점검

> **규모 → 권장 maturity**: S1→L1, S2→L2, S3→L3, S4→L4
