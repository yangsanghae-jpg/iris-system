# Nanoln 지표 계산 트리 \(L0\~L4 완전 연산 구조\)

**계산 트리 핵심 규칙**

1\. 모든 상위 지표는 **하위 지표의 집계/가공 결과**로만 산출 \(임의 입력 불가\)

2\. 모든 최종값은 **L4 원천데이터 100% 기반**으로 연산

3\. L3\(부서책임지표\)는 계산값이 아닌 **상위 결과에 대한 책임 매핑 지표**로 별도 운영

4\. 수치 비연계 = 계산 트리 붕괴 = 지표 신뢰도 0

## 6\. 계산 트리 비연계 시 발생하는 치명적 문제 \(계산 로직 기준\)

**1\. 상위 지표가 허수로 전환됨**

L0/L1 값이 하위 L2/L4 데이터와 무관하게 독립 산출되면, 실제 공장 상태와 전혀 다른 수치가 경영에 보고됨 \(가장 치명적\)

**2\. 원인 분석 자체가 불가능**

경영 리스크\(L0\)가 악화되어도 어떤 L2 변수\(대기시간/설비다운/불량률\) 때문인지 수치상 추적 불가

**3\. 개선 효과를 수치로 검증 불가**

현장에서 개선을 진행해도 상위 지표 연산에 반영되지 않아 성과 증명 불가, 개선 동기 상실

**4\. 데이터 기준 통일 붕괴**

각 부서별 자체 계산식 사용 → 동일 지표 다른 숫자 발생 → 관리 자체가 불가능

**5\. 프로젝트가 단순 대시보드 이미지화로 전락**

계산 트리가 살아있어야만 IE 낭비 분석·추적 관리가 가능하며, 연계가 끊어지면 고객이 요구한 **엑셀업무 경감 \+ 원인추적 \+ 책임관리** 전체 목표가 소멸
