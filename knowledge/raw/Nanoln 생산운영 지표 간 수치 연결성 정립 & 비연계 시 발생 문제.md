# Nanoln 생산운영 지표 간 수치 연결성 정립 \&amp; 비연계 시 발생 문제

**핵심 전제**：본 L0\~L4 지표 트리는 **상위 경영결과 ↔ 하위 현장원인**이 1:多 인과관계로 연결되어야 정상 운영됨
단순 개별 수치 나열은 무의미하며, **L4 원천데이터가 누적 → L2 IE흐름지표 산출 → L1 회사성과 확정 → L0 경영리스크 도출**이 유일한 정상 로직

## 1\. 전체 지표 수치 연결 메인 로직 \(정식 표준\)

**\[L4 현장 원천데이터\] → 집계/가공 → \[L2 IE 운영흐름 지표\] → 결과 정합 → \[L1 회사 성과지표\] → 리스크 종합 → \[L0 경영 Cockpit\]**

**L3 부서책임지표**：L0/L1 결과 악화의 직접 원인이 되는 부서별 관리 수치로, 전 계층을 가로지르는 책임 매핑 레이어

**절대 규칙**：상위 지표는 독립적으로 존재할 수 없으며, 모든 경영·성과 수치는 반드시 하위 현장 데이터로 드릴다운 검증이 가능해야 함

## 3\. 수치 간 연결이 끊어지면 안 되는 핵심 이유 \(프로젝트·경영·현업 리스크\)

본 지표体系는 **결과지표만 보는 관리가 아닌, 원인추적 개선형 관리**가 핵심이므로 수치 단절은 모든 프로젝트 목표를 무효화함

### 3\.1 프로젝트 차원 리스크 \(컨설팅/개발 실패 원인\)

- **단순 리포트 쓰레기화**：각 지표가 개별 숫자로만 존재하면, 현업 엑셀 데이터를 화면에 옮기는 것에 불과해 프로젝트 본질\(IE 낭비개선·원인추적\)이 사라짐

- **범위통제 불가**：수치 연결성이 없으면 P0/P1/P2 우선순위가 무의미해지고, 고객의 무분별한 리포트 추가 요구를 막을 수 없어 프로젝트 범위가 붕괴됨

- **개발 재작업 발생**：상하위 데이터 연계 로직 없이 개발하면, 후에 원인추적 기능 추가 시 전체 화면·데이터 로직 재수정이 필수로 발생

### 3\.2 경영관리 차원 리스크 \(경영진 관리 실패\)

- **경영진이 원인을 알 수 없음**：L0 리스크 숫자만 악화되는데, 어떤 공정/설비/자재 문제인지 드릴다운 불가 → 경영 의사결정이 막힘

- **성과 관리의 공정성 상실**：결과만 보고 부서를 평가하게 되어, 타 부서 연계 문제를 특정 부서 책임으로 전가하는 책임 떠넘기기 발생

- **선제 관리 불가**：결과지표\(L1\)만 보고 원인지표\(L2/L4\) 연계가 안 되면, 문제가 터진 후에야 파악하는 사후관리만 가능

### 3\.3 현업 운영 차원 리스크 \(개선 불가·업무 부하 증가\)

- **개선 우선순위 선정 불가**：수치 간 인과관계가 없으면 어떤 낭비·불량이 회사 손실에 큰 영향을 주는지 판단할 수 없어 개선 업무가 무의미하게 분산됨

- **엑셀 수작업 완전 대체 불가**：데이터 연계가 끊어지면 시스템에서 통합 분석이 불가능해 현업이 기존 엑셀 취합을 계속 해야 하며, 업무 부하가 전혀 줄지 않음

- **반복 문제 재발**：품질/설비/납기 이상의 원인 추적이 불가능해 동일 문제가 지속 발생, 공정 품질·운영 안정화 불가

### 3\.4 데이터 신뢰도 차원 리스크

- **수치 정합성 검증 불가**：상위 결과와 하위 원천데이터가 연계되지 않으면 숫자 오류·누락·기준 불일치를 발견할 수 없어 지표 자체의 신뢰도가 붕괴됨

- **데이터 표준화 의미 상실**：지표별 계산식·기준이 연계되지 않아 부서별 다른 기준으로 수치를 산출, 비교 관리 자체가 불가능

## 4\. 최종 결론

Nanoln 프로젝트는 **리포트 화면 제작 프로젝트가 아닌, 공장 데이터 인과관계를 복원하는 컨설팅 프로젝트**이다\.
